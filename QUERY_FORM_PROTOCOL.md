# Query form × response: verified-facts-query-form-v1

Status: frozen before new model collection. This is the revised Run 1 following
review of the initial brief. Run 0 is offline. Run 2 is deferred for redesign;
there is no dose package or live dose collection in this change.

## Question and hypothesis

Does presenting the target as a descriptive profile, rather than a lookup key,
increase the cost of asking for visible reasoning before a classification answer?
The working hypothesis is a shift toward pattern classification under the profile
cue. A query-form interaction would constrain that account, but would not identify
an internal task representation or distinguish all retrieval explanations.

The cue study found direct 48/48 and visible 23/48 correct on conflicting records.
The constrained-cue follow-up was 48/48 in both arms. Explanation, answer-order,
and revision results also motivate testing what happens before an answer.
Mistral prefix-v2 base results were direct 24/24 and visible 15/24, but its replay
gate failed; the later mapping study did not localize a decisive prefix transition.
The separate query-role-001 screen was 144/144 correct across literal, encoded,
and downstream variants, so its decision was `stop_this_screen`. Those ceiling
results do not establish general absence of reasoning harm.

## Amendments to the original brief

1. Sensitivity is the average of **+1 correct target label, −1 other target
   record label, 0 pattern label** over the two variants. Its range is [−1,1],
   matching the cue estimand and the thresholds below. Equivalently, sum the
   two ±0.5 scores; do not average them a second time.
2. Filler is generated by copying a fixed neutral paragraph within the same
   assistant response. There is one user message, no assistant prefill and no
   extra “Now answer” turn. Approximately 320 words were chosen before collection,
   informed by archived visible-output medians of approximately 318 GPT-4o and
   322 Mistral words. This is an imperfect content/control manipulation, not a
   pure token-budget intervention. Copy adherence and observed lengths are reported.
3. The improved rationale coder handles multiline record statements and rejects
   bare inferential comparisons. It retains the original regex flags and evidence
   excerpts. Its provisional categories never enter the spending decision.
4. The spending decision is explicit, requires replication and conservative
   full-plan bounds, and can be inconclusive. It does not execute another study.

## Design and exact prompts

24 fresh worlds; seed `2026101001`; identifiers `qf-list-000` through `023`;
fresh plate prefix `U`. Use `exception_counterfactual.make_world` and a copy of
the cue ternary role assignment. All six permutations of record_1/record_2/pattern
roles occur twice per target climate. The target is the only changed cell between
record variants. Same-climate peers all carry the pattern label. Other-climate
labels are split 3/2 between the target's two possible record labels.

Each world crosses two record variants × profile/key query × direct/visible/filler
response: 12 tasks, 288 planned calls per model. Task order is shuffled within world
with `rng_for(PROTOCOL_VERSION, "schedule", seed, index)`. There is no cross-call
conversation history. Worlds, task order, analysis plan and complete `plan.json`
are byte-identical across model configurations. Provider settings are frozen
separately in `run_config.json`; execution and every attempt bind both hashes.

The one user message contains unchanged `INTRO` from `exception_explanation.core`,
a blank line, the exact cue seven-column table in `world["order"]`, a blank line,
the query block, unchanged `QUESTION`, and the arm instruction. The query block
is either the five `describe(target)` lines or just `License plate: {target_id}`.
Between query forms, every byte before and after that block is identical within
each world, variant and arm. Headers and answer keys in previews are not sent.

Direct instruction: `Output only ANSWER: followed by A, B, or C.`

Visible instruction: `Think step by step before answering. Write your reasoning,
then put ANSWER: followed by A, B, or C alone on the final line.`

Filler instruction: `First copy the following neutral paragraph exactly, without
its delimiters. Do not add an explanation. Then put ANSWER: followed by A, B, or C
alone on the final line.` The fixed paragraph follows inside `<neutral_paragraph>`
delimiters. Its exact bytes are the `FILLER` constant in `exception_query_form/core.py`.
It contains no vehicle, class or table content and no standalone A, B or C tokens.
Outer whitespace is ignored when testing an exact copy; internal bytes must match.

`prepare` writes `preview.md` with all 12 prompts for world 000 and `preview.json`
with all 288 exact provider requests. Reviewed, source-controlled copies are in
`previews/query-form-gpt4o/` and `previews/query-form-mistral/`.

## Providers, scoring and collection

GPT-4o: `gpt-4o-2024-08-06`, temperature 0, 1,000 completion tokens in every arm.
Mistral: `mistral-small-2603`, temperature 0, `reasoning_effort="none"`, 1,600 tokens
in every arm; endpoint from Mistral prefix-v2. Both use timeout 120 seconds and
cumulative cap 316 attempts. Config field sets are exact; credentials come only
from the named environment variable and never enter plans or journals.

Use the correctness-blind terminal parser from `exception_mistral_map_v3.parser`.
Also record strict final `ANSWER: X` formatting, pre-answer text, answer-only status,
output-contract adherence, filler exactness and pre-answer word count. Formatting
noncompliance is retained and never used to select a better answer. Provider
truncation/refusal/malformed returned bodies or unparseable answers are terminal
`invalid` data and do not stop collection. Model mismatch is retained and stops
collection. A missing model identity makes a response invalid and prevents a
positive spending decision. There are no hidden retries.

Only recorded transport errors can be retried with `--resume --retry-errors`.
An unresolved `started` attempt after interruption cannot safely be known to have
returned no answer and requires review; this runner does not resample it.
Each attempt is atomically written before and after its single HTTP request.
All attempts, including errors, count toward 316. Existing completed/invalid tasks
can never be retried. A fixed schedule, raw-response rescoring, and source/config
hash checks protect resume. Mock mode is prominently labeled **SIMULATED** and
cannot be resumed live or yield `proceed_to_dose`.

## Estimands and uncertainty

Within each (query, arm), average the two variants for accuracy and sensitivity.
The unit is an independent world, not a call. Report six cell means for each
metric, four direct-minus-visible/filler simple effects, and the interaction:

`(profile_direct − profile_visible) − (key_direct − key_visible)`.

Sensitivity interaction is primary; accuracy interaction and simple effects are
secondary. Resample whole worlds 10,000 times, seed 981723; report descriptive
95% percentile intervals. For each estimand use the worlds complete on every
required variant/cell and report that denominator. Sign tests are exact two-sided
binomial tests on nonzero world differences (ties separately). They test sign
balance, not a null about mean magnitude. Secondary intervals/tests are unadjusted.
These 24 stratified generated worlds are a limited synthetic population; bootstrap
intervals do not cover all wording, model, seed or backend variability.

Report per-cell pattern choices, invalid/unreturned counts, format controls,
completion tokens and pre-answer lengths. Full-plan bounds hold scorable answers
fixed and range each missing/invalid answer over A/B/C, respecting contrast signs:
accuracy missing scores span [0,1], sensitivity spans [−1,1]. Bounds are not CIs.
Degenerate bootstrap intervals under ceiling performance do not establish equivalence.

The Run-0 coder runs on all scorable visible outputs; include shares by query,
correctness and code. Invalids are reported outside this text-code denominator.
Wrong-response codes are outcome-conditioned descriptions, not causal mediators.

## Predeclared predictions and outcome table

| ID | Prediction on corrected sensitivity scale |
|---|---|
| P1 | Profile direct − visible ≥ 0.30 |
| P2 | Key direct − visible ≤ 0.10 |
| P3 | Interaction ≥ 0.20; exact two-sided sign p < 0.05 |
| P4 | Direct − filler ≤ 0.10 in each query form |
| P5 | Among wrong visible responses, never_stated + relabeled_missing ≥ 75%; exploratory automated coding, never a gate |
| P6 | Mistral has the same positive interaction sign and interaction ≥ 0.20 |

All predictions appear alongside estimates whether supported or not. The following
is a practical spending rule and does not establish a mechanism or equivalence.
Both models must return all 288 planned responses, match the same plan, have no
identity failures, and each have at least 22 complete primary-contrast worlds.
For each model and query, ≥95% of all 48 planned filler responses must copy the
paragraph exactly, and ≥95% of visible responses must contain pre-answer text.
There is no answer-selection or retry based on these controls.

| Condition, in precedence order | Decision |
|---|---|
| Mock input | `simulated_only` |
| Incomplete plan or invalid model/config/design identity | No proceed; specific failure reason |
| Control adherence below threshold or fewer than 22 complete primary worlds | Inconclusive; no proceed |
| Either query's filler-harm full-plan lower bound > 0.10 and descriptive CI lower endpoint > 0 | `stop_tokens_account_live` |
| Both queries' visible-harm full-plan lower bounds > 0.10 and both CI lower endpoints > 0 | `stop_query_form` |
| Profile-harm full-plan lower bound ≥ 0.30; key-harm upper bound ≤ 0.10; interaction lower bound ≥ 0.20 and sign p < 0.05; both filler-harm upper bounds ≤ 0.10 | Local `eligible_for_dose_review` |
| Other complete results | `inconclusive` |
| Both distinct live models locally eligible, recomputed from journals with the same plan hash | `proceed_to_dose` |

A locally eligible analysis without the other model returns `awaiting_replication`.
`analyze --replication` audits the other directory and writes the combined decision
only to the primary output directory. Conservative missing-answer effect bounds
do not remove selection concerns in the complete-world sign test; report its
denominator and all missingness. Neither a positive decision nor the command
automatically executes Run 2. A redesigned dose protocol must be frozen first.

## Stopping rule and limitations

Fixed 288 planned calls per model, no extension, no outcome-based world selection.
The first 12 calls check execution, not scientific promise; resume the fixed plan
regardless of observed accuracy unless a transport/identity/cap failure blocks it.
The cap allows explicit transport retries, not replacement of invalid outputs.

The profile changes token length and the availability of semantic/nuisance cues;
it is not a pure manipulation of latent task recognition. Neutral copying differs
from reasoning in input instructions, length and content, and can itself change
computation. A clean filler comparison narrows explanations without proving that
token count is irrelevant. Lexical rationale codes are fallible and are not
faithful windows into computation. Results concern these two fixed models and
this synthetic task. Models at temperature zero may still vary across calls.

Run 2 requires redesign: cue peers are 4/4 pattern-labeled, not 0.75; balanced
6/20-row worlds have 2/9 peers and cannot realize all specified fractions exactly;
only five distinct descriptions exist per climate; and the proposed nonpattern
peer rule changes peer labels across target-record variants. Position effects
alone do not uniquely identify retrieval failure.

## Commands

From the repository root (the existing package manifest is intentionally unchanged):

```sh
python3 -m unittest discover -s tests -v
python3 code_rationales.py --run runs/cue-001 --out analysis/rationales/cue-001 --sample 20 --seed 981723
# Repeat for explanation-001, order-001, revision-001, mistral-prefix-v2-001.
python3 -m exception_query_form prepare --config configs/query_form_gpt4o.json --output runs/query-form-gpt4o-001
python3 -m exception_query_form run --config configs/query_form_gpt4o.json --output runs/query-form-gpt4o-001 --max-calls 12
python3 -m exception_query_form run --config configs/query_form_gpt4o.json --output runs/query-form-gpt4o-001 --max-calls 288 --resume
python3 -m exception_query_form analyze --output runs/query-form-gpt4o-001
python3 -m exception_query_form prepare --config configs/query_form_mistral.json --output runs/query-form-mistral-001
python3 -m exception_query_form run --config configs/query_form_mistral.json --output runs/query-form-mistral-001 --max-calls 12
python3 -m exception_query_form run --config configs/query_form_mistral.json --output runs/query-form-mistral-001 --max-calls 288 --resume
python3 -m exception_query_form analyze --output runs/query-form-mistral-001 --replication runs/query-form-gpt4o-001
```

On macOS, prefix long `run` commands with `caffeinate -i`. Credentials must already
be set in `OPENAI_API_KEY` / `MISTRAL_API_KEY`; never place values in command files.
For an entirely offline smoke test, use a fresh output and `run --mock --max-calls 288`.
Never reuse a mock directory for live calls. `prepare` and `analyze` require no key
and make no network calls.

## Literature motivating the design

- Liu et al., [Mind Your Step (ICML 2025)](https://proceedings.mlr.press/v267/liu25t.html): reasoning can impair performance in some task settings; the exception task is a direct ancestor of this paradigm.
- Pan et al., [What In-Context Learning “Learns” In-Context](https://arxiv.org/abs/2305.09731): task recognition and task learning motivate separating cues from record evidence; this experiment does not observe either internally.
- Liu et al., [Lost in the Middle](https://arxiv.org/abs/2307.03172): input position can affect use of context, motivating but not uniquely interpreting later position controls.
- Turpin et al., [Language Models Don't Always Say What They Think](https://arxiv.org/abs/2305.04388): written reasoning can be unfaithful, limiting rationale-based mechanism claims.
