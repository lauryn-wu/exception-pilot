# Provider contracts inspected on 2026-10-13

Only public documentation was read. No account/model-list requests, paid completions or capability calls were made. **Account access, chosen production judge identities and real annotation quality are NOT TESTED.** `configs/study2_review_offline.json` therefore has null model IDs, false contract/access flags and `live_enabled=false`. Configuration has to be completed before a live command can run; adapters never substitute models.

Returned text is parsed once and locally schema-validated, including exact enum case; invalid returns are terminal. Provider recommendations to retry malformed/truncated results do **not** override this patch's no-resampling rule. HTTP errors, timeouts and incomplete/refused responses retain raw sanitized bodies and never become negative votes. A changed returned model identity is terminal invalid.

Serving infrastructure can still change.

The implementation's output cap is configurable from 1 through 32,768; the offline template uses 4,096. Verify that the exact selected model supports both its chosen cap and settings before recording `contract_verified=true`. OpenAI settings allow explicit temperature and/or a documented `reasoning` object. Anthropic settings allow documented temperature/thinking/effort; effort is placed in `output_config`, not the top-level request. Do not combine settings unsupported by the chosen model. Empty settings mean provider defaults and must be consciously frozen as such. No undocumented model names, schema parameters, endpoint variations, retries or token-counting API calls are generated.

Usage accounting keeps raw provider usage and configured rates. OpenAI `output_tokens` includes billed reasoning (also reported separately in its details); Anthropic output totals likewise must not have thinking added a second time. Cached input/cache creation are accounted for with separate rates where supplied. [OpenAI response usage reference](https://developers.openai.com/api/reference/resources/responses/methods/create) and [Anthropic Messages reference](https://platform.claude.com/docs/en/api/messages/create) describe the response fields; the OpenAI reference full-page fetch exceeded the browsing tool's page-size limit, so request/response schema checks also used the fetched structured-output guide. No pricing or latency is claimed as measured. The user-supplied rate table is an estimate, not a billing guarantee.

Adapters use `http.client.HTTPSConnection` directly, not SDK retry defaults. One call performs one POST; redirects and automatic resends are absent. Raw request IDs, response IDs, configured and returned model identity, request/response payloads, UTC timestamps, monotonic latency and usage are journaled. Secrets and authorization headers are excluded. The standard-library judge environment imports neither torch nor transformers. Explicit local-tokenizer checks and Qwen execution are different stages/environments.
