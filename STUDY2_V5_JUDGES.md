# Optional v5 independent family judges

The pushed v5 baseline (`a40b120`) already supplied blinded manual two-reviewer
annotations, third-review reconciliation, exact source spans, and independent edit
verification. It did **not** dispatch J1/J2/J3. This patch adds that optional path
in `exception_study2_v5_judges`, outside the frozen scientific package. Existing
v5 code, tests, protocol, configuration, source hashes and runs remain unchanged.
The existing manual workflow in the runbook remains an alternative.

## Design and guarantees

- Two separately frozen system rubrics and structured schemas: Family M detects
  erasure (prose or reconstructed unknown/blank verified cells) and observational
  miscopy; Family O detects correct acknowledgment, conflict, and explicit
  overriding after acknowledgment. O is not the old missingness-only detector.
- J1/J2 receive identical original prompt/table and pre-answer text for each family,
  in independent stateless calls. Configured model identities are preserved; separate
  requests do not establish statistical independence or require three different models.
  Neither sees another vote, final-answer scores,
  2A measurements, edited responses, or intervention effectiveness. The pre-answer
  boundary is the existing v5 parser; no new scientific boundary is introduced.
- J3 receives the same blinded view only when at least one event has no conclusive
  exact J1/J2 pair, including uncertain, invalid or failed initial calls. J3 is an
  independent adjudicating vote, not a conversation with J1/J2. Exact pairs resolve
  each event in J1/J2, J1/J3, J2/J3 priority order. A lone J3 vote cannot establish an
  event. No pair stays uncertain/invalid; no unavailable evidence becomes absence.
- All five event types and all visible responses in the chosen complete attempted
  batch are retained, including failed, incorrect, invalid and truncated originals.
  Failed originals need no judge calls and remain invalid. Clean/mixed/unknown M/O
  histories are derived from the frozen spans, not outcomes or keyword classifiers.
- Each semantic criterion requires a separate rating and reason. Valid JSON is
  only a schema check. A present event also needs exact unique Unicode alignment,
  explicit passing semantic ratings, and (for O) a prior accepted acknowledgment.
  Exported boolean certificates come from those explicit ratings in an agreeing
  pair; they are **fallible judge assertions, not semantic proof**. Raw ratings,
  disagreements and failures stay in the journal. Absence/exclusion requires an
  explicit complete-text review. Non-passing ratings do not silently become `true`.
- Detection never drafts, verifies or executes interventions. The existing separate
  drafter/independent named verifier, exact draft hash, every semantic edit check,
  tokenizer roundtrip and eligibility gates remain mandatory. No edit-verification
  certificates are generated by this module. Manual review remains available,
  including when automated decisions are unresolved; use a fresh manual directory
  and preserve the automated artifacts rather than changing their votes in place.
- The unchanged v4/shared provider, strict response parser, cost accounting and
  append-only journal source are reused under isolated M/O namespaces. There is no
  global monkeypatching of v4. Both families share one request/spend ledger and
  invocation budget. Requests are serial, with zero retries and no automatic
  resend of failed or ambiguously interrupted calls. A rerun uses completed calls;
  an unfinished call is retained as unavailable. Explicitly bounded fresh J3 is
  adjudication, not a retry of J1/J2. A later new review must use a new directory and
  must not overwrite the original failed run.
- Source, model/backend, plan, row, view, judge settings, rubric, schema, reused
  provider code, additive judge code, and operation identities are frozen. Initial
  Git revision is recorded. Paths are relative to the review directory; moving
  source and review together is supported. Credentials belong only in environment
  variables and are redacted/refused in persisted request data by the shared client.

## Target-row convention

`target_row_position` is **zero-based among vehicle data rows**, excluding the
Markdown header and separator. Value **9 means the tenth vehicle**, currently the
last vehicle. It is `table.splitlines()[11]` (the twelfth Markdown line). It is not
`world['target']`: that is an index into the unsorted item array. The mapping is
`world['order'][9] == world['target']`. Judge views include the explicit convention,
one-based display number, plate, exact row, and verified class. All 480 frozen tasks
are regression checked. Scientific prompts and table ordering are not modified.

## Request ceilings and budgets

| Scope | Visible responses | J1/J2 calls (two families) | Conditional J3 maximum | Total maximum |
|---|---:|---:|---:|---:|
| Four-world pilot | 16 | 64 | 32 | 96 |
| Remaining 56 worlds | 224 | 896 | 448 | 1,344 |
| All 60 worlds | 240 | 960 | 480 | 1,440 |

Unavailable originals reduce these ceilings. The supplied config is **offline,
unconfigured, and capped at 96 total requests** and $10 estimated spend, with
4,096 maximum output tokens per request (pilot maximum 393,216 judge output tokens).
This is a cap, not a usage prediction. Rates are intentionally unset; no dollar
cost or real-model availability is claimed. Set current verified rates and exact
model identities before enabling live mode. The shared conservative byte-based
input reservation is an estimate, not a provider billing guarantee. A budget stop
preserves pending work; it is never recorded as an absent event. Both per-invocation
`--max-calls` and the frozen aggregate limit apply across M and O. Wall limits stop
scheduling; they cannot cancel an already dispatched request. Each request has its
configured timeout. Existing Qwen workload counts are unchanged.

## RunPod commands

Run from the existing checkout/environment; a GPU is unnecessary for judging.
Update only with a clean checkout and preserve all original/result directories.
This additive patch preserves the `a40b120` v5 scientific hash, so those frozen v5
plans remain readable. Other scientific revisions still require their matching code.

```bash
cd /workspace/exception-pilot
git status --short
git fetch origin codex/study2-v5-evidence-interventions
git switch codex/study2-v5-evidence-interventions
git merge --ff-only origin/codex/study2-v5-evidence-interventions
source /workspace/venvs/study2-qwen3/bin/activate
export PYTHONDONTWRITEBYTECODE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
```

Use the existing `$RUN_V5` and `$V5_HOME` from the scientific runbook. First prepare
and inspect an **offline** review (this never contacts a provider):

```bash
export JUDGES_V5="$V5_HOME/pilot-judges-offline"
python -m exception_study2_v5_judges prepare --source "$RUN_V5" --output "$JUDGES_V5" --scope pilot
python -m exception_study2_v5_judges run --output "$JUDGES_V5" --max-calls 4
```

Expected: zero attempted calls and stop reason `OFFLINE`. Inspect `policy.json` and
`judge-plan-v5.json`. Do not change these frozen files. Source population and both
prompts are fixed before calls. This preparation is separate from scientific 2A/2B.

For **later explicitly authorized paid execution**, copy the example config to a
private local path, set all three exact configured provider/model identities, verified
provider contract/access flags, current billing rates, desired finite request/spend
limits, and `live_enabled: true`. Do not put keys in the config. Model aliases or
provider support have not been tested here; verify actual structured-output support
and pin snapshot identifiers where available. No paid model is silently substituted.
Set required provider keys securely in the shell environment (never commit them).
Prepare a **fresh** live review and begin with at most four calls:

```bash
export JUDGES_V5="$V5_HOME/pilot-judges-live"
python -m exception_study2_v5_judges prepare --source "$RUN_V5" --output "$JUDGES_V5" --scope pilot --config "$V5_HOME/judge-config-live.json"
python -m exception_study2_v5_judges run --output "$JUDGES_V5" --live-judges --max-calls 4 --wall-seconds 600
```

**STOP and inspect** `judge-operations/`, `invocations/`, `reports/` for provider
identity, schema support, failures, cost/usage and semantics. Budget stops are
expected with four calls. Do not erase failed operations to retry. If proceeding
with the same frozen policy is appropriate, a separate explicit command resumes
remaining J1/J2 and conditional J3 within the original aggregate ceiling:

```bash
python -m exception_study2_v5_judges run --output "$JUDGES_V5" --live-judges --max-calls 96 --wall-seconds 3600
```

`--stage initial` may be used to run only J1/J2; the default `all` adds only
conditional J3. Neither mode starts Qwen, readouts, interventions or later worlds.
After the review is terminal, explicitly export without network calls:

```bash
python -m exception_study2_v5_judges export --output "$JUDGES_V5"
export ANNOTATIONS_V5="$JUDGES_V5/annotation-manifest-v5.json"
python -m exception_study2_v5 annotation-summary --source "$RUN_V5" --scope pilot --annotations "$ANNOTATIONS_V5"
```

**STOP** if export reports incomplete. Pending calls must not be turned into negative
annotations. Terminal unresolved/invalid events remain visible in the exported
manifest, excluded from automatic event eligibility. Inspect them and all accepted
spans before the runbook's separate edit preparation and independent verification.
The export includes judge provenance and both family resolutions. No scientific
stage is launched by exporting. Do not run `--scope all` after separately reviewing
pilot and remaining and claim cross-directory request caching.

## Offline validation and limits

```bash
PYTHONDONTWRITEBYTECODE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python -m unittest discover -s tests -p test_study2_v5_judges.py -v
```

Tests inject synthetic originals and mock transports, block network/model loading,
and exercise independent prompts/requests, semantic checks, row indexing, exact
spans, conditional J3, unavailable/ambiguous/failed calls, budget resumption,
model/source mismatches, manual verification and unchanged source artifacts.
See `audits/study2-v5-judges/OFFLINE_ACCEPTANCE.md` for exact complete-suite results.
Real provider contract/access, judging quality, M/O prevalence, Qwen behavior and
intervention effects remain **not tested** by this patch. No paid judging or GPU
inference was executed.
