# Current Qwen native-thinking screen v1

This is a bounded exploratory test of whether native thinking increases a conflicting feature pattern's effect when the target record is supplied. It extends the controlled-v2 task; it is not an exact replication of the historical tables or greedy Qwen3-32B runs. Historical code, protocols, journals and validation gates are unchanged.

The frozen design contains 24 new worlds × two recorded-label variants × support/conflict × native thinking off/on × original/lookup wording: **384 responses**. Each response has a **4,096-token total output cap**, including thinking, final text and EOS. The scientific ceiling is **1,572,864 generated tokens**. There is one sample per cell, no replacement for wrong or truncated answers, and no automatic budget change or subsequent experiment.

## Construction and audit

Seed 2026102101 and namespace `study2-current-qwen-native-screen-v1` are independent of the old manifest. The generator reuses controlled-v2's 16-row layout, four unanimous same-climate peers, target-last placement and four nuisance profiles (multiplicities 4/4/4/3 in the background). Four prespecified background count families are (4,5,6), (6,5,4), (4,4,7), (5,5,5), each crossed with all six A/B/C role permutations. Fresh nuisance assignments, row orders, IDs and descriptors produce 24 distinct scaffolds even after label names, identifiers and descriptor synonyms are removed. Two climates have 12 worlds each. Target profiles and doubled audit markers rotate before any outputs are observed.

Target variants change only the target's recorded cell. The support/conflict change swaps eight background labels, leaving the target and class counts unchanged. The code audits the final rendered tables, not only generator metadata. It reuses the historical target-excluded association, feature-match, count, majority, parity, profile and held-out histogram tests. Counterbalances are checked for every relation and target variant. Absence definitions and conditional missing-cell instructions are removed; scientific prompts and tables contain no `MISSING`. Both modes use the same final-answer instruction and question. No extra reasoning instruction is added.

These controls do not erase per-table correlations. The in-sample histogram-only accuracy bound for this manifest is **0.625**; it is not held-out performance or evidence that a model uses counts. No audited shortcut is perfect on its nonempty covered set across the full manifest. The complete audit is exported with the design. Position-based lookup remains available because the target is last. Six worlds share each construction family. Treating all 24 as independent families would overstate precision. The generator is fixed before model outcomes; it must not be redesigned to obtain a preferred result.

## Model and decoding

`Qwen/Qwen3.8-27B`, model/tokenizer/processor revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`; official small assets and all weight shards have a SHA-256 lock in `exception_study2_current/assets.json`. Weights and tokenizers are read only from explicit local paths. No remote-code execution, quantization or CPU weight offload is requested. Precision is BF16; the official hybrid model's recurrent state uses float32. One text-only vLLM backend, one GPU, one request at a time, 8,192-token context, no prefix cache. The driver and GPU must support the pinned runtime; real loading remains untested until smoke.

Pinned Python dependencies: vLLM 0.26.0, torch 2.11.0, Transformers 5.8.0, tokenizers 0.22.2, huggingface-hub 1.7.1, Jinja2 3.1.6. Use a new Python 3.12 environment. These versions were checked against official release metadata and interfaces; the CUDA stack has not been executed here.

Sampling is explicit and shared: temperature 1.0, top-p .95, top-k 20, min-p 0, presence/frequency penalties 0, repetition penalty 1, n=1. Nonzero temperature selects sampling in vLLM; historical `do_sample=False` is not inherited. No answer constraint, bad-word filter, forced thinking cutoff, stop string or logit bias is used. EOS IDs come from the pinned generation config. Seeds are frozen per world/wording and matched across variants, background conditions and thinking modes. This matches requested seeds, not necessarily the random-number consumption of unequal trajectories. Complete request settings, runtime versions and resolved vLLM sampling defaults are frozen before dispatch; each return records its resolved sampling parameters. vLLM's model-provided generation defaults are disabled.

The official template accepts `enable_thinking`, `preserve_thinking=True`, and on-mode `reasoning_effort='medium'`. Medium is a template choice, not a numerical effort knob. It produces different text from low and xhigh; unsupported effort raises an error. The adapter verifies this with the real pinned tokenizer. In thinking-on prompts, `<think>` is already part of the input. Thinking-off prompts retain the official empty block. Token IDs and boundaries are derived from these assets, never copied from Qwen3-32B. The real tokenizer has opening/closing IDs 248068/248069 and EOS IDs 248044/248046. Fresh user-only conversations are rendered separately for every cell.

Official references: [model card](https://huggingface.co/Qwen/Qwen3.8-27B), [pinned template](https://huggingface.co/Qwen/Qwen3.8-27B/blob/1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0/chat_template.jinja), [vLLM recipe](https://recipes.vllm.ai/Qwen/Qwen3.8-27B), [pinned LLM API](https://github.com/vllm-project/vllm/blob/v0.26.0/vllm/entrypoints/llm.py), [sampling parameters](https://github.com/vllm-project/vllm/blob/v0.26.0/vllm/sampling_params.py).

## Technical smoke and execution

Smoke uses two separate synthetic questions in both modes (four originals, cap 256), followed by four exact-token-prefix continuations, each with the remaining portion of that 256-token budget. It has at most eight immutable requests and a conservative 2,048-token bound. Prefix calls are frozen only once their source operations return; input is the original rendered IDs plus a saved output prefix, with no template reconstruction. Sampled suffixes need not reproduce the original suffix. Passing checks token/text identity, both channels, EOS, a valid final format and preservation of supplied prefix tokens; it does not establish distribution equivalence or scientific accuracy. If originals cannot supply prefixes, remaining smoke slots are dependency-blocked, not silently replaced.

A scientific plan can be frozen before smoke completes but cannot execute until all eight real-model checks pass. There is no judge-calibration gate and no old 64/896 pilot/main stage. A passing smoke binds the backend identity for the screen. Default commands are offline. Explicit `--live-qwen` is required to load a model. Pending work is found first; fully cached runs, inspection and analysis load no weights. One load occurs per invocation with executable work. `--max-new` bounds dispatches, including failed ones. First backend exception stops that invocation; later never-started cells remain eligible on resume. Returned wrong, malformed and truncated outputs are cached permanently. No automatic retry for failed or ambiguous operations.

The existing immutable Session, atomic writes, exclusive lock and conservative journal reader are reused. Request identities include protocol, source tokens/text, model/tokenizer/template/runtime, effort, sampler, budget and seed. Orphan dispatches and recognized temporary journal debris are held. `recover` quarantines bytes with provenance; it never promotes a temporary return or authorizes another sample. Preserve failed/ambiguous calls for forensic review. Do not delete journals to resume.

## Scoring and uncertainty

Only the final channel after the thinking close is scored. Its stripped text must be exactly A, B or C with observed EOS and consistent token/text metadata. Thinking text cannot rescue a missing or invalid final answer. An unclosed thinking block at the cap is truncated, not a pattern choice. Full raw IDs/text and half-open channel token boundaries are retained.

Primary original-wording contrast: `(accuracy_on_support − accuracy_on_conflict) − (accuracy_off_support − accuracy_off_conflict)`. Average the two target variants within each world first. Positive values mean a larger conflict penalty with thinking. The primary descriptive 95% interval bootstraps the **four construction blocks**, retaining six worlds per block; a 24-world bootstrap is labeled sensitivity only. Four clusters give limited uncertainty resolution. Lookup receives its own secondary contrast. This is not powered confirmation.

All 384 cells appear in accounting. Returned invalid/truncated replies count as unsuccessful fixed-budget outcomes. Missing, failed and ambiguous operations remain unavailable, not wrong; accuracy bounds are shown and the contrast is withheld until all relevant cells have returns. Valid wrong labels, conflict-pattern choices, other wrong labels, invalid final text, truncation and missing finals are separate counts. A truncation-driven gap is not evidence of pattern substitution. Support answers cannot distinguish copying the record from following the pattern. Length, repetition, timing and memory summaries do not change scoring or eligibility.

## Evidence and stopping

Export includes frozen requests, full immutable journals and invocation records, smoke provenance, code/template/weight identities, derived analysis, complete traces and a manual-review CSV. Review fields start as `not_reviewed`, with `absent` and `present` reserved for human review. Correct record mention, explicit false absence, record uncertainty, feature-based justification and target inclusion in feature/class associations can coexist. Each has its own quote and zero-based half-open Unicode offsets in raw text. Label-only thinking-off replies offer fewer observable statements. Nothing is automatically annotated from keywords. No activations are collected.

Stop after this screen. False-absence prevalence is not a project gate. No transfer, steering, evidence interventions, paid judges or other follow-up is launched.
